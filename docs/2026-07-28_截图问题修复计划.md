# 截图问题修复计划

> 日期：2026-07-28  
> 范围：工作台时间线、持续分析/切片队列、放大预览、设置页窄宽布局  
> 依据：用户提供的 13 张运行截图与当前实现代码核对。  
> 原则：不改变录制流、预览流、分析流的既有三轴模型；优先消除状态误读、布局遮挡与误操作。

### 1.1 非缺陷的事实校准

1. 预览、录制、持续分析不是同一进度来源。预览通过 MSE 连接，录制写入本地文件，持续分析读取录制进度；约 20 秒差距在直播场景中可合理存在。
2. `pending/refining` 切片必须先确认才可导出，这一限制是为了避免近似边界直接导出，并非导出队列故障。
3. 共享进样开启时显示风险提示符合产品约束；本计划不改变其默认架构。

## 2. P0：让三轴进度可理解、可核验

### 目标

用户能够一眼区分“正在看到的预览位置”“磁盘已录制时长”“AI 已扫描位置”，并理解预览落后时仍可正常录制和分析。

### 修改范围

- `lsc-electron/src/pages/Workbench/index.tsx`
- `lsc-electron/src/pages/Workbench/components/ControlBar.tsx`
- 视需要新增 `lsc-electron/src/pages/Workbench/components/TimelineStatus.tsx`
- `lsc-electron/src/utils/timelineCoords.ts`（只补充展示辅助函数，不改三轴换算规则）

### 实施步骤

1. 定义前端展示 DTO `TimelineProgressSummary`：
   - `previewPosition`：当前 MSE 播放位置；
   - `recordedDuration`：`computeRecordedDurationHint()` 结果；
   - `analysisScannedDuration`：连续分析状态的已扫描时长；
   - `previewDelay = max(0, recordedDuration - previewPosition)`；
   - `axis`：当前控制栏处于 `preview/common/recording_review` 的哪一条轴。
2. 控制栏原有 `00:01:14 / 00:01:14 已录 00:01:38` 改为语义化文本，例如：
   - `预览 01:14 · 录制 01:38 · 延迟 24 秒`
   - 持续分析运行时再显示 `分析至 01:40`。
3. 当延迟超过 5 秒时，显示非阻断提示（info 色，不使用 error），hover 说明：
   - “预览与录制为独立流。切片标记以当前预览内容为准，录制和分析可先于预览推进。”
4. 只有在录制已停止、连续分析也已完成且差距持续扩大时，才标记为异常状态；不可把正常直播延迟当作失败。
5. 保持现有逻辑：预览开启且 `followLive` 时，不能用录制时长强行扩大可拖动预览轴。现有 `resolveLiveContentSpan()` 的限制必须保留。

### 验收标准

- 单房间录制、预览、持续分析同时运行时，三项时长都带名称且可独立理解；
- 预览落后 10–30 秒不会出现错误 Toast；
- 用户无法把预览播放头拖到 MSE 尚不存在的录制未来区；
- 进入 `recording_review` 后，控制栏明确显示“录制回看轴”。

## 3. P1：待调切片与批量导出的可操作性

### 修改范围

- `lsc-electron/src/pages/Workbench/components/ClipList.tsx`
- `lsc-electron/src/pages/Workbench/index.tsx`
- 可能新增/补充 `lsc-electron/src/utils/clipNaming.ts`

### 实施步骤

1. 将单条待调切片的勾选按钮改为带文字的次级按钮“确认”，窄宽时才降级为图标。
2. `待调` 标签的 tooltip 固定说明“确认边界后即可导出”；有 `boundary_evidence` 时在点击信息图标后显示完整依据。
3. 顶部操作根据状态分组：
   - 存在待调项：显示 `确认全部（N）`；
   - 存在可导出项：显示 `导出全部（N）`；
   - 仅存在待调项时，导出全部禁用并给出原因，而不是只靠灰色外观。
4. 确认/确认并导出前，在行内显示将采用的入出点，避免“确认”的实际语义不明。
5. 统一 AI 回合标签和房间显示名的命名规范：`TryTry_R01` 可保留为切片编号，但应在 tooltip 中展示“主播名 · 回合号”。

### 验收标准

- 待调切片无需猜测图标即可完成确认；
- 导出禁用时能看见原因；
- “确认全部”不会修改边界，仅改变确认状态；
- 批量导出仅提交已确认且未在队列中的切片。

## 4. P1：放大预览只保留一套控制系统

### 修改范围

- `lsc-electron/src/pages/Workbench/components/RoomCard.tsx`
- 必要时 `lsc-electron/src/components/VideoPreview.tsx`

### 实施步骤

1. 卡片模式：保留自定义底栏（画质、静音、放大、关闭预览），原生 video controls 关闭。
2. 放大模式：启用原生 `<video controls>`，隐藏自定义底栏中的静音、全屏和停止预览按钮。
3. 放大模式仅保留右上角“缩小”按钮；若仍需切换画质，移动到视频区域外或单独的轻量菜单，不能与原生控制栏重叠。
4. 核验静音状态仍由 `localMuted` / 全局静音保持，不因切换模式反转。

### 验收标准

- 放大后底部只存在一套媒体控制栏；
- 缩小后卡片自定义控制恢复；
- `Esc`、右上角“缩小”、原生全屏均不导致 MSE Player 重建或黑屏；
- 切换前后静音与画质状态保持一致。

## 6. P2：消除 CRF、停止分析和切片计数的歧义

### 6.1 CRF 滑块

**文件：** `lsc-electron/src/pages/Settings/index.tsx`

- 将固定 marks 改成 `18 / 推荐 23 / 28` 的纯刻度标签；
- 当前值只在滑块 tooltip 或紧邻标题显示，文案为“当前 CRF：26”；
- 添加说明：数值越低质量越高、体积越大；NVENC 的 CQ 与 x264 CRF 显示语义一致但后端参数不同。

### 6.2 停止持续分析的流程状态

**文件：** `lsc-electron/src/pages/Workbench/index.tsx`、`python-backend/handlers/room_handler.py`

1. 先用集成测试确认：录制进行中请求停止持续分析时，后端实际返回的 phase、是否继续补尾、是否允许重新启动。
2. 若后端允许停止：弹窗让用户选择“停止录制并收尾分析”或“仅停止分析”；后者要明确提示尾部不会继续检测。
3. 若后端不允许停止：前端按钮在录制中禁用并显示“请先停止录制”。
4. 工作台状态统一展示 `扫描中 / 请求停止 / 收尾中 / 已完成 / 失败`，不要只依赖按钮文字。

### 6.3 切片列表 0 与待调 1 的一致性诊断

**文件：** `lsc-electron/src/store/appStore.ts`、`lsc-electron/src/pages/Workbench/index.tsx`

- 对 `clips` 的写入来源记录开发日志：全量 set、单条 add、删除、持续分析推送；记录 clip stable id 数量；
- 检查 `rooms_updated` 或连续分析状态回调是否意外执行 `setClips([])`；
- 用“启动分析 → 产生待调 → 切换设置页 → 返回工作台 → 停止/收尾”复现；
- 仅在复现到状态丢失后再修复，避免把不同截图时点误判为数据丢失。

## 8. 实施顺序、回归与风险

1. **先 P1-预览控制与 P1-设置布局**：纯前端、影响面小，优先去除确定的视觉缺陷。
2. **再 P0-三轴状态呈现**：只新增展示，不改变换算逻辑，必须用真实直播流验证。
3. **然后 P1-待调切片交互**：需要覆盖单条、批量、确认并导出和队列中四类状态。
4. **最后 P2/P3**：先复现再修，避免根据单张截图修改正确逻辑。

### 必跑验证

```powershell
Push-Location lsc-electron
npx tsc --noEmit
Pop-Location

python -m pytest -q
```

### 手工验收场景

1. 一路直播：预览、录制、持续分析并行，制造 15–30 秒预览延迟。
2. AI 产生一条 pending 回合：确认、确认并导出、确认全部、批量导出。
3. 放大/缩小预览循环 10 次，验证没有双控制栏、黑屏或静音反转。
4. Settings 在 480、525、768、1280 px 宽度下检查日志、路径、导出预设与 Cookie 卡片。
5. 停止录制后立即停止持续分析，观察进入 finalizing、补齐尾部、完成的完整状态链路。

## 9. 本计划明确不做的事项

- 不将预览与录制合并为同一 FFmpeg 流；默认独立双进程架构不变。
- 不允许用户在尚未收到 MSE 数据的“录制未来区”播放或直接打标。
- 不放宽待调/近似定位切片的导出保护。
- 不回显 Cookie 值，也不改变 Cookie 持久化协议。
