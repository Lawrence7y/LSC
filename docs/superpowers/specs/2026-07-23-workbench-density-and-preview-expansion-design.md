# 工作台信息收紧与预览区域放大设计

## 目标

减少工作台时间线和切片列表的重复信息；让设置页在有限宽度内以“解释 + 选项”同行呈现；修复预览区域首次放大时原生与自定义控件重叠、以及“缩小”按钮覆盖设置抽屉的问题。

## 约束

- 保留单轨时间线、拖拽、缩放、I/O 标记、精修、AI 候选点击、时间坐标换算和后端协议。
- 保留 MSE 播放器实例；区域放大不能通过卸载或重建播放器实现。
- 不新增依赖，不修改录制、导出、确认或设置保存的业务协议。
- 仅改动本需求涉及的前端文件和针对性守卫测试；不覆盖工作区已有未提交改动。

## 预览区域放大

### 根因

区域放大时 RoomCard 同时开启 HTML video 的原生 controls，又继续渲染自定义的画质、静音、放大、停止和“缩小”浮层。因此浏览器的两条原生控制条与应用控制条处于同一区域。另一个“缩小”按钮的 z-index: 10000 高于 Ant Design 设置抽屉的默认层级，且设置抽屉打开时没有清除工作台的 expandedRoomId。

### 方案

- 区域放大仍由 expandedRoomId 驱动，保留原来的 MSE 实例和房间卡片内布局。
- 放大与未放大都禁用浏览器原生 video controls；视频区域只使用应用内的统一底部控制栏。
- 放大状态下控制栏保留画质、静音、缩小、关闭预览等现有能力；不得与第二套视频控件叠加。
- “缩小”按钮放在预览容器的局部叠层中，层级只高于该容器内的视频和控制栏，禁止使用全局层级数值。
- Workbench 订阅 settingsDrawerOpen。抽屉变为打开状态时，立即将 expandedRoomId 置空；Esc、缩小、关闭预览和移除房间沿用并收敛到同一放大状态。

### 验收

1. 首次和后续每次区域放大都只显示一套应用内控件。
2. 打开设置抽屉后，预览恢复普通卡片尺寸，页面上没有残留“缩小”按钮。
3. 关闭抽屉不会重新放大预览。
4. MSE 播放器不因区域放大或收起而重新初始化。

## 时间线

- 标尺只显示左右边界时间；播放头时间只在拖拽或悬停时作为局部提示。
- 控制条中部只保留一处当前 / 总时长。录制时以“已录”作为补充状态，不能与同一数值重复展示。
- 播放、I/O、倍速、缩放和回到直播等现有操作保持可达；优先通过紧凑分组和 tooltip 降低文字密度。

## 切片列表

- 顶部摘要以“待确认 N”为最强信息，其次是总数和已确认/可导出数量。
- 确认和导出必须保持顺序状态：待确认 → 已确认可导出 → 导出中/已导出/失败。
- 待确认条目的主操作是“确认”；确认完成后主操作变为“导出”。批量入口分别处理待确认条目和已确认可导出条目，不能绕过确认直接导出。
- 单条时间保留一行“起点 — 终点 · 时长”；详情、删除和低频操作收进次级菜单或图标入口。

## 设置页

- 复用现有 SettingsSection、SettingsRow 和左侧导航，不另建设置页面。
- 左侧导航在悬停时显示指针；当前分组使用品牌色、左侧细指示条和 aria-current 表示，点击和滚动均能更新当前项。
- 常规设置行改为“名称 + 一句解释 + 控件”同一横行；在窄宽度下才换行，避免为了说明而增加整行高度。
- 路径选择、Cookie 文本区域、日志查看等天然多行内容保留块级布局，不强行压缩。

## 验证

- 添加或更新前端守卫，覆盖：放大预览不启用原生 controls、设置抽屉打开时收起区域放大、缩小按钮不存在全局高层级、时间线重复时间文本的结构约束、切片确认状态与导出门槛、设置行说明结构和导航可访问性。
- 执行相关 Python 前端守卫、TypeScript 无输出类型检查和 git diff --check。
- 在本地 Electron 中手动验证：首次放大、再次放大、打开/关闭设置抽屉、Esc、缩小、确认一条切片后导出，以及窄窗口设置行换行。
