# 无畏契约 HUD 回合边界持续分析设计

> **日期：** 2026-07-19
> **状态：** 已确认，待用户审阅书面 spec
> **替代边界契约：** 本文覆盖旧设计中“结算画面或下一回合买枪均可作为终点”的歧义；本功能统一以**下一回合买枪阶段开始**作为终点。

## 目标

在 `valorant_round` 持续分析模式下，按完整回合切分无畏契约直播画面：

- 起点是当前回合买枪阶段结束、屏障解除后的第一个交战画面；
- 终点是下一回合买枪阶段出现的第一帧；
- 结算、回放和回合间过渡属于刚结束的回合；
- 只有起点、终点都确认的闭合回合才加入切片列表；
- 保持现有“加入列表后由用户确认，不自动执行 FFmpeg 导出”的产品契约。

同时降低持续分析开销：复用现有 FFmpeg 抽帧、OpenCV、相位状态和 `clip_queued` 链路，以低分辨率 HUD 结构检测替代反复长窗 OCR。

## 现场调查

### 样本

- 原始录像：`D:\desktop\新建文件夹\新建文件夹\新建文件夹\bilibili_room_6ff915\recording_20260719_144951_d3f865.mp4`
- 原始时长：4686 秒
- 用户实际导出：20 个 MP4，时长 38–139 秒
- 分析 sidecar：`recording_20260719_144951_d3f865.analysis.json`

### 复现结果

关键帧检查确认样本中同时存在以下错误：

- 切片从买枪阶段中途开始；
- 切片从交战阶段中途开始；
- 切片在交战阶段中途结束；
- 一个切片跨越两个或更多回合；
- 地图加载、赛后界面和英雄选择界面被识别为回合；
- 同一录制中出现重复 `round_key` 和重复回合编号。

sidecar 共记录 29 个候选：

| 指标 | 结果 |
|---|---:|
| OCR 确认回合 | 0 |
| `start_by=audio` | 29 |
| `end_by=chime` | 18 |
| `end_by=inferred` | 8 |
| `end_by=audio` | 3 |
| 重复 `round_key` | `round-000007`、`round-000159` |

### 根因

1. 样本游戏 UI 为俄语。现有回合 OCR 只将中文“购买阶段/准备阶段/购买”识别为买枪状态，结算词只覆盖中文和英文。
2. 当前 RapidOCR 模型不能稳定识别西里尔字母。对清晰的 `ФАЗА ПОКУПОК`，实际输出为 `A3A nOKynok`，因此增加准确俄语字符串也不能可靠修复。
3. OCR 边界失效后，检测退化为直播整轨音频 RMS、钟声和推断边界。解说、音乐、技能声和界面声使音频能量无法表达完整回合结构。
4. `_continuous_analysis_loop` 仍将这些纯音频候选通过 `list_only=True`、`confirm_status='pending'` 广播为 `clip_queued`，错误候选因此进入切片列表并可被用户确认导出。
5. 当前持续分析会反复回看 120–360 秒并执行密集 OCR；既没有修复语言问题，又重复处理旧帧。

结论：固定增加或减少数秒只能掩盖个别样本，无法修复跨回合、半回合和菜单误切。修复点必须是共享的 HUD 边界识别与入列门禁。

## 决策

采用**语言无关的 HUD 状态转换**作为无畏契约完整回合的权威边界。

不采用以下方案：

- 不只补俄语关键词：当前 OCR 会把西里尔字母错误转写，规则不稳定；
- 不更换多语言 OCR 模型：会增加模型、依赖、内存和持续推理成本；
- 不训练新模型：本需求只需识别固定 HUD 状态，现有 OpenCV 足够；
- 不继续让纯音频候选进入切片列表：音频仅保留为调度提示和诊断信号。

## 范围

### 包含

- `valorant_round` 持续分析；
- 单房间和现有已对齐多房间映射；
- 录制过程中的增量检测与停录收尾；
- 闭合回合的列表入列、去重和边界更新；
- 中文、英文、俄语及其他语言客户端的同布局 HUD。

### 不包含

- 自动导出；
- 新设置页面或语言选择器；
- 击杀高光、精彩度评分或英雄识别；
- 对隐藏 HUD、自定义严重遮挡 HUD、纯音频或非游戏画面猜测回合；
- 非 `valorant_round` 模式行为变更。

## 边界契约

### 起点

必须先稳定观察到买枪阶段，再稳定观察到买枪状态消失且比赛 HUD 仍存在。起点取这一轮“非买枪”连续观察中的第一帧时间戳，不取第二帧确认时刻。

这表示切片不包含当前回合买枪期，但保留屏障解除后的完整交战。

### 终点

回合打开后，下一次稳定观察到买枪阶段时闭合回合。终点取这一轮“买枪”连续观察中的第一帧时间戳，不取买枪结束、下一回合开战或结算文字时间。

这表示上一回合的胜负结算、死亡回放和回合间过渡都被保留，下一回合买枪画面不进入上一切片。

### 稳定观察

- 常态每 1 秒观察一帧；
- 相同状态连续命中 2 帧才确认转换；
- 转换时间使用连续命中的第一帧，因此确认延迟约 1 秒，但不把延迟写入边界；
- 起止目标误差不超过 1.5 秒；
- 有效闭合时长必须满足 `5s <= duration <= 180s`。强 HUD 双边界不再使用现有 35 秒最小时长，避免漏掉极短回合；超过 180 秒视为丢失边界并重新锚定。

## HUD 观察器

在现有 `lsc/analyzer/round_detector.py` 内复用 `_detect_round_phase_markers` 的抽帧与 OpenCV 路径，不创建第二套分析管线。

每个低分辨率观察帧只产生四项内部信号：

| 信号 | 含义 |
|---|---|
| `hud_present` | 顶部比分、计时器和双方状态条的固定布局存在 |
| `buy_banner_present` | 中央买枪横幅的两行结构和高对比区域存在 |
| `timer_contradicts_buy` | 只有在倒计时被高置信读出且明确不可能属于买枪阶段时为真 |
| `frame_valid` | 不是全黑、加载、英雄选择、桌面或赛后页面 |

买枪状态由结构组合判定，不要求识别横幅文字：

```text
is_buy = frame_valid
         and hud_present
         and buy_banner_present
         and not timer_contradicts_buy
```

倒计时读不到数字时，`timer_contradicts_buy=false`，不得单独否决清晰的买枪横幅；该信号只用于排除高置信识别出的结算横幅和其他中央大字。具体阈值是模块内部常量，不新增用户设置。实现时用用户样本与现有测试夹具一次性校准。

现有中文、英文 OCR 可以保留为诊断信息或提高置信度，但不再是买枪状态的必需条件，也不得改变结构状态机已经确认的终点。

## 状态机

复用现有持续任务状态和 `phase_scheduler`，不增加可并行运行的第二状态机。任务状态只需保留：

- `last_stable_hud_state`；
- `state_run_first_ts` 与连续命中数；
- `pending_start`；
- `last_processed_frame_ts`；
- 已发布的 `round_key` 集合。

状态流如下：

```text
等待买枪
  └─ 稳定 buy ─► 等待开战
                    └─ 稳定 non-buy ─► 回合已打开（记录 pending_start）
                                          └─ 稳定 buy ─► 闭合并入列
                                                               └─ 等待开战
```

约束：

- 任务从交战中途启动时不猜起点，必须等下一次完整 `buy -> non-buy` 转换；
- `hud_present=false` 持续不超过 5 秒时保留状态，覆盖短暂转场或遮挡；
- 无有效 HUD 超过 5 秒时使当前开放回合失效，回到“等待买枪”，禁止跨地图、赛后或英雄选择拼接；
- 用户取消持续分析时丢弃开放回合，不入列；
- 停录时只有已观察到下一买枪起点的回合才能闭合，开放尾不以文件结尾代替。

音频 RMS、钟声、能量塌陷可以改变分析状态文案或触发更快轮询，但不能写 `pending_start`、不能写终点、不能创建 `clip_queued`。

## 增量扫描与性能

现有分析线程和 `_analysis_semaphore` 保持不变，避免录制、预览与分析争抢 FFmpeg。

扫描改为前向游标：

1. 每次只处理 `last_processed_frame_ts` 之后的新 HUD 帧；
2. 为 FFmpeg seek 和帧时间戳误差保留最多 3 秒重叠；
3. 通过时间戳去重重叠帧；
4. 每帧只裁顶部 HUD 与中央横幅的小 ROI；
5. 常态 1 FPS，不对已处理的 120–360 秒窗口重复 OCR；
6. 落后时按时间顺序分段追赶，禁止跳到直播尾部而漏掉中间状态转换；
7. 停录 finalize 从最后游标继续处理剩余帧，不默认重扫完整文件。只有任务状态缺失或检测记录损坏时才执行一次全文件低分辨率 HUD 扫描。

性能目标：同一视频帧最多进入一次结构分类，3 秒解码重叠除外；无畏契约持续分析主路径不调用文本 OCR 时也能完成回合切分。

## 回合对象与去重

闭合回合产生以下字段：

```json
{
  "start": 321.0,
  "end": 409.0,
  "phase": "combat",
  "start_by": "buy_exit_visual",
  "end_by": "next_buy_visual",
  "boundary_source": "valorant_hud_transition",
  "boundary_confidence": 0.92,
  "round_key": "hud-round-000321"
}
```

字段契约：

- `boundary_confidence` 为两端结构置信度的较小值，范围 `[0, 1]`；
- `round_key` 使用已确认起点的整秒桶生成，替代现有 10 秒桶；相同窗口重扫仍命中同一 key，不同回合不会因起点接近而碰撞；
- 旧音频候选可以保留在分析诊断结果中，但不得带 `boundary_source=valorant_hud_transition`，也不得进入自动列表路径；
- `_merge_round_windows` 只允许同 `round_key` 更新边界，不能以大范围时间重叠把两个已确认 HUD 回合合并；
- 用户开始精修后继续沿用 `_refined_round_keys` 冻结边界。

## 切片列表数据流

复用现有链路：

```text
HUD 双边界闭合
  -> 回合去重
  -> _validate_synced_analysis_targets
  -> 主房时间映射到目标房间
  -> _auto_export_highlights(list_only=True, confirm_status="pending")
  -> clip_queued
  -> Workbench Zustand clips
```

要求：

- 每个闭合回合只广播一次首次 `clip_queued`；边界在用户精修前发生有效变化时发送 `upsert=true`；
- `clip_queued` 必须包含 `round_key`、`start`、`end`、`boundary_source` 和 `boundary_confidence`；
- `confirm_status` 保持 `pending`，用户确认后才允许导出；
- 不写 `_deferred_export_jobs`，不自动调用 `queue_export`；
- 多房间仍只分析主房，按现有 `recording_start_mono + content_offset` 映射后，每个有效目标房间加入一条切片；
- 单个副房映射失败不影响主房入列，并沿用现有 `mapping_fallback` 提示。

前端已经统一监听 `clip_queued` 并支持 `room_id + round_key` upsert，因此本功能不新增页面或列表入口。若前端类型是封闭声明，只补充两个可选字段；不新增另一种事件。

## 错误处理

| 情况 | 行为 |
|---|---|
| OpenCV 不可用 | 状态报告“HUD 边界检测不可用”；不回退为音频自动入列 |
| HUD 被长期遮挡或隐藏 | 丢弃开放回合，等待下一次稳定买枪状态 |
| 录制从交战中途开始 | 等下一回合买枪，再从后续完整回合开始切 |
| 只有起点、没有下一买枪 | 保持开放状态；停止或取消时丢弃 |
| 候选超过 180 秒 | 判定丢边界，丢弃并重新等待买枪 |
| FFmpeg 抽帧超时 | 保留游标前状态并重试同一小窗；不得推进 `last_processed_frame_ts` |
| 多房同步映射失败 | 主房照常入列，副房失败走现有 fallback 提示 |
| 非游戏/地图加载/英雄选择/赛后 | `frame_valid=false`，不得创建或闭合回合 |

## 测试策略

### 纯逻辑状态机

使用观察序列测试，不依赖 FFmpeg 或 OCR：

1. `buy, buy, combat, combat, buy, buy` 只产生一个回合；起点取第一个 combat 时间，终点取第二段第一个 buy 时间。
2. 从 `combat` 启动不产生回合，直到观察到完整的下一轮 `buy -> combat -> buy`。
3. 连续 1 帧误判不触发转换。
4. HUD 消失 5 秒内恢复时保持状态；超过 5 秒使开放回合失效。
5. 只有音频信号、没有 HUD 转换时不产生回合。
6. 重叠窗口重复观察相同时间戳时只产生一个 `round_key`。
7. 5–180 秒的强双边界回合允许入列；超出范围的候选丢弃。

### HUD 分类器

使用小尺寸裁剪图测试以下类别：

- 中文、英文、俄语买枪横幅；
- 正常交战 HUD；
- 胜负结算横幅；
- 比分板打开；
- 地图加载、英雄选择、赛后和桌面画面。

CI 夹具只保留必要 HUD ROI，不提交完整用户录像。用户样本继续用于本地端到端验收。

### 后端契约

- 纯音频/`inferred`/`chime` 候选不调用列表入列路径；
- HUD 闭合回合调用 `_auto_export_highlights(..., list_only=True, confirm_status='pending')`；
- 不创建 deferred export，不调用 `queue_export`；
- 相同 `round_key` 重扫只 upsert、不重复添加；
- 多房映射后各房间边界保持相同内容时刻。

### 前端契约

- `clip_queued` 首次事件增加一条切片；
- `upsert=true` 更新原条目而不是新增；
- pending 回合仍需用户确认；
- 不依赖 `continuous_highlights` 再次添加同一切片。

## 验收标准

在用户提供的原始录像上进行人工关键帧复核：

1. 每个输出切片的第一帧位于买枪横幅消失后，误差不超过 1.5 秒。
2. 每个输出切片的结束点位于下一回合买枪横幅首次出现处，误差不超过 1.5 秒。
3. 结算和回合间过渡保留在上一切片中，下一回合买枪内容不进入上一切片。
4. 不产生从交战中途开始或在交战中途结束的切片。
5. 不产生跨两个回合的切片。
6. 地图加载、英雄选择、赛后和桌面画面不进入切片列表。
7. 不再出现由 10 秒起点桶造成的不同回合 `round_key` 碰撞。
8. 纯音频候选数可以保留作诊断，但其 `clip_queued` 数必须为 0。
9. 闭合 HUD 回合在检测后加入切片列表，不自动导出。
10. 相关现有测试与新增状态机、HUD 分类器、列表门禁测试全部通过。
