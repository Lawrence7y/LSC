# Valorant 双来源帧标注与试验模型设计

日期：2026-07-20

状态：待用户书面审阅

目标：用一段 POV 录像和一段赛事转播录像完成第一轮五分类帧标注、模型训练、内部评估与 shadow 全链路验证。

## 1. 范围与结论边界

本轮输入为两段相互独立的 Valorant 录像：一段第一人称 POV，一段赛事转播；每段约 30–60 分钟。采用“分层抽帧 + 候选初标 + 人工视觉复核”，不使用旧 OCR/音频边界结果直接充当真值。

本轮产物是试验模型，用于证明抽帧、标注、训练、ONNX 导出、持续分析和 shadow 观测链路可运行。因为每种来源只有一个录制会话，内部测试不能证明跨主播、跨赛事或跨 HUD 版本的泛化能力，也不能替代正式发布盲测。

不在本轮范围内：

- 自动生成未经人工复核的生产标签；
- 用相邻随机帧拆分制造虚高指标；
- 将原录像、抽帧图片或本地模型提交到 Git；
- 未经过 shadow 和门禁就启用正式切片入列。

## 2. 数据位置与安全边界

原录像放在仓库已忽略的本地目录：

```text
datasets/valorant_phase/raw/
├── pov.<视频扩展名>
└── broadcast.<视频扩展名>
```

所有抽帧、标签、数据集和模型产物均放在 `datasets/valorant_phase/` 下。该目录已由 `.gitignore` 排除。原始视频路径只写入本地 manifest，不进入提交。

当前工作区存在 3 个未跟踪标注脚本：

- `scripts/valorant_vision/build_label_queue.py`
- `scripts/valorant_vision/serve_label_ui.py`
- `scripts/valorant_vision/apply_interval_labels.py`

它们包含硬编码录像路径、固定 4 秒采样和粗区间标签，且当前按“POV 全部 train、转播全部 val”划分，不满足本设计的数据隔离规则。实施时优先审计和最小化复用这些工具，但不得原样运行后把输出视为合格真值，也不得覆盖其未提交内容。

## 3. 数据划分

每段录像独立按时间块划分：

- 前 65%：`train`
- 中间 15%：`val`
- 最后 20%：`test`

相邻划分边界两侧各排除约 15 秒，总隔离带约 30 秒，不抽取样本。这样保证 POV 和 broadcast 都出现在三个 split 中，同时降低同一转场附近的相邻帧泄漏。

`test` 仅在模型和阈值冻结后运行一次评估，不参与训练、阈值选择和补标决策。首次查看 test 结果后，该测试段即视为已暴露；如果据此修改模型，下一次验收必须换用新的保留时间段或新录像。由于 train/val/test 仍来自同两段录像，最终报告必须标注为“内部时间块测试”。

## 4. 五类标签定义

| 标签 | 定义 | 关键边界 |
|---|---|---|
| `non_game` | 桌面、加载、选人、暂停、广告、舞台、设置菜单，以及没有有效实时回合 HUD 的画面 | 回到有效比赛画面后才离开该类 |
| `buy` | 买枪或准备阶段，包含屏障尚未解除的实时画面 | 屏障解除后的第一帧转为 `combat` |
| `combat` | 屏障解除后的正常实时回合交战 | 结算 UI 首次稳定出现后转为 `result` |
| `result` | 当前回合结束后的胜负结算画面 | Replay 或下一回合买枪画面出现后离开 |
| `replay` | 官方 Replay、击杀回放或明显脱离实时比赛的回放画面 | 回到实时比赛 HUD 后离开 |

标注只依据当前帧实际显示的状态，不用前后剧情替当前帧猜标签。无法可靠判断的转场帧先标记为待复核，不强行归类。

## 5. 抽帧与标注流程

### 5.1 视频预检

先检查两段录像的解码能力、时长、分辨率、帧率和时间轴连续性。视频无法解码、时间戳倒退或关键区间损坏时停止对应视频的抽帧，并记录具体位置。

### 5.2 分层抽帧

- 稳定状态按每 3–5 秒一帧采样；
- 买枪结束、结算出现、Replay 切入/切出、非游戏画面切换等边界前后 3 秒，按每 0.25–0.5 秒一帧加密；
- HUD 遮挡、模糊、比分面板变化和非常规转场作为难例额外保留；
- `(video_id, timestamp_sec)` 去重，避免重复帧压倒边界样本。

预计最终保留约 1,200–2,500 帧，实际数量由录像内容决定，不以凑数量为目标。

### 5.3 初标与视觉复核

低频扫描先划出候选状态区间，再生成候选标签。候选标签不是训练真值，必须经过逐帧视觉复核后才写入 `manifest.jsonl`。

全部边界帧复核一次；稳定状态随机复核至少 10%。模糊或有争议的相邻帧通过可视化伴侣并排展示，仅把真正无法从画面判断的少量样本交给用户确认。

### 5.4 数据集产物

```text
datasets/valorant_phase/
├── raw/
├── annotations/
│   ├── queue.json
│   ├── labels.json
│   └── manifest.jsonl
├── train/{non_game,buy,combat,result,replay}/
├── val/{non_game,buy,combat,result,replay}/
├── test/{non_game,buy,combat,result,replay}/
└── model/
    ├── valorant_phase_v1.onnx
    └── valorant_phase_v1.json
```

manifest 沿用现有契约字段：`video_id`、`video_path`、`timestamp_sec`、`label`、`split`、`source_type`、`session_id` 和可选 `notes`。

## 6. 训练与模型契约

训练复用现有 `scripts/valorant_vision/train_export.py` 和 MobileNetV3-Small，不新增模型框架。训练与运行时统一使用 224×224 RGB resize、相同 normalize 参数，以及 Softmax 概率输出。

导出流程先生成 ONNX，再生成实际由运行时加载的 INT8 artifact，并写出含 SHA-256、类序、阈值和数据集版本的 JSON 契约。任何类别少于 50 个已复核训练样本时停止训练并报告缺口，不复制相邻帧凑数。

如果两段录像都缺少某一类别，例如没有 Replay，则停止五分类训练并请求补充包含该类别的小段素材。

## 7. 试验验收门槛

### 7.1 帧分类

- 验证集 Macro F1 ≥ 0.90；
- `buy`、`result` precision ≥ 0.93；
- `non_game`、`replay` recall ≥ 0.90；
- FP32 与 INT8 在固定抽样帧上的 argmax 一致率 ≥ 98%；
- ONNX 输出必须通过现有概率、维度、有限值、SHA-256 和元数据契约校验。

### 7.2 内部回合评估

- 回合 recall ≥ 0.80；
- 入列 precision ≥ 0.90；
- 已确认回合边界误差 P95 ≤ 2 秒；
- 评估按 `video_id` 隔离匹配，不允许 POV 预测匹配转播真值。

这些是试验门槛，低于正式发布 spec 的指标。即使全部通过，模型也只能进入 shadow，不得直接视为生产模型。

### 7.3 Shadow 运行

进入 shadow 前先修复 Electron 后端环境白名单，使 `LSC_VALORANT_MODEL_DIR` 与 `LSC_VALORANT_VISION_SHADOW` 能传递到 Python 后端。shadow 期间：

- hybrid 检测正常运行并记录模型版本、provider、候选回合数和错误；
- 不产生 `clip_queued`；
- 停止持续分析后 3 秒内结束当前 FFmpeg/短推理批次；
- 不遗留孤儿 FFmpeg；
- 模型或契约错误必须 fail-closed，不回退旧音频/OCR 边界。

## 8. 失败分析与补标循环

在首次 test 前，迭代只使用 train/val：如果验证集未达到试验门槛，先输出混淆矩阵、按来源指标和验证集错误样本清单。只针对最常见误分类与边界难例补标，再重新训练；不通过盲目增加 epoch 掩盖数据问题。test 运行后不得再用其错误样本调参并继续宣称同一 test 是盲测。

如果 INT8 一致率不足，保留失败样本并停止部署，检查量化支持和导出图。若视频损坏、标签缺类或测试段没有完整回合，则报告数据缺口并等待补充，不降低门槛制造通过结果。

## 9. 完成定义

本轮完成必须同时具备：

1. 两种来源的本地标注 manifest 与可复现抽帧数据集；
2. 标签审计统计和难例记录；
3. 通过契约校验的 INT8 ONNX 与 JSON；
4. 帧分类报告与按视频隔离的内部回合评估报告；
5. Electron 环境变量透传修复及回归测试；
6. 一次 shadow 实测记录，包括停止延迟和孤儿 FFmpeg 检查；
7. 明确列出尚未满足的正式发布条件：更多独立 POV/转播会话、真正跨录像盲测和持续浸泡。
