# 工作台状态栏与单轨时间线设计

## 目标

改善多房间工作台在持续分析期间的可读性：用户能在不阅读技术统计的情况下判断分析是否仍在进行、是否有待确认切片，并能在同一条时间轴上辨认切片、AI 候选、选区与播放位置。

## 范围

仅修改 Electron 前端的以下区域：

- `AnalysisProgress` 的紧凑状态栏。
- `Timeline` 的单一时间轴视觉层级。
- `ClipList` 的标题摘要、状态可见性和大列表行高。

不修改 WebSocket 消息、后端持续分析逻辑、切片确认/导出流程、时间轴坐标转换或数据模型；不引入依赖。

## 已确认的界面规则

### 持续分析运行条

- 主状态统一使用“分析中 / 等待录制 / 等待新片段 / 收尾中 / 已完成 / 异常”，不把“音频推进中”作为主状态。
- 当任务没有固定且已完成的扫描范围时，不显示百分比或 `已分析 / 总时长`；显示“已跟进至 HH:MM:SS”和“刚刚/秒前更新”。
- 仅在扫描 Worker 正在处理一个明确范围，或最终收尾阶段，显示进度条；进行中的直播跟进不显示 `100%`。
- “待确认”和“已入列”保持可见；导出摘要仅在任一计数非零时显示。
- 结束分析维持危险动作视觉，不改停止确认行为。

### 单轨时间线

- 保持一个可缩放、可拖拽的时间轴，不增加多轨或新的操作模式。
- 青色主线和播放头表示预览位置；播放头使用短竖线加圆点，便于与刻度和选区对齐。
- 蓝色实心区间表示已入列/手动切片；橙色虚线或半透明区间表示 AI 待确认候选。
- 当前选区是蓝色低透明底和细边框；精修区间沿用蓝色而不新增颜色语义。
- 绿/红入出点位于最上层并保留现有拖拽、右键删除和标签行为。
- 没有切片或候选时，时间轴退回为与播放器一致的极简进度条；时间码只保留轴首尾和控制栏当前时间。

### 切片列表

- 标题摘要明确显示“共 N”及“待确认 N”，不再用 `N/N待` 缩写。
- 每行持续显示一个最关键状态；不将确认、导出、重试等已有行为改成新流程。
- 虚拟化行高覆盖状态、时间和导出进度，避免超过 40 条切片时裁剪内容。

## 实现边界

复用现有 `ContinuousAnalysisStatus`、`ExportSummary`、`ClipSegment`、高光点击和时间轴事件。样式继续使用现有 CSS 变量：青色为主进度，绿色为入点，红色为出点，蓝色为切片/选区，橙色为待确认 AI 候选。

## 验证

先为各规则新增前端静态守卫测试，确认测试在旧实现失败；再做最小实现使其通过。完成后运行：

```powershell
python -m pytest tests/test_frontend_stability_guards.py -q
npm exec tsc -- --noEmit
```

并以现有截图尺寸检查紧凑状态栏与单轨时间线没有溢出、百分比不再与“分析中”冲突。
