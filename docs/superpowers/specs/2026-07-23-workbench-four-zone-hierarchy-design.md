# 工作台四区层级与最小边界设计

## 决策

将工作台整理为四个固定区域，保持既有多房间、录制、时间轴、切片、持续分析和导出能力不变：

1. 顶部会话栏：第一行仅保留“添加房间”“开始录制”“停止录制”；第二行收纳全选、对齐、静音、刷新和更多低频工具。
2. 中部房间区：保留现有 `RoomCard` 网格，作为多房间并行监看与选择区。
3. 底部编辑区：保留现有 `ControlBar`/`Timeline`、播放、I/O、拖拽、缩放、精修、DVR/Live 跟随及公共时间轴坐标逻辑。
4. 右侧切片队列：移除“添加房间”；以一个队列显示“待确认、导出中、已完成”摘要及按下一步动作排序的片段。持续分析入口置于此处。

设置仍以右侧抽屉呈现；打开抽屉时，左侧菜单的设置项必须使用抽屉状态作为选中态，不能只依赖 URL。

## 用户流

```text
添加房间 → 选择房间 → 开始/停止录制
                         ↓
                  房间网格并行监看
                         ↓
             底部时间轴定位、I/O、精修
                         ↓
          右侧队列确认 → 导出 → 打开结果
```

顶部不再同时承载持续分析、导出结果和所有批量工具。持续分析产生的候选片段进入右侧队列，用户在同一处完成确认与导出。

## 代码边界

`Workbench/index.tsx` 保留为页面编排层，负责四区布局、既有子组件组装、时间轴联动和 WebSocket 状态订阅。仅提取以下两段已有业务流程：

| 新边界 | 负责内容 | 不负责内容 |
|---|---|---|
| `useRoomBatchActions` | 全选、批量录制/停止、批量静音 | 房间卡渲染、音频对齐、时间轴坐标、后端协议定义 |
| `useClipWorkflow` | 导出提交、导出确认弹窗、剪映草稿会话 | 切片确认/精修、时间轴拖拽、播放头、房间媒体控制 |

不引入新依赖、新的全局状态或第二套时间轴坐标转换。`Timeline`、`ControlBar`、`RoomCard`、`ClipList` 的对外行为及 WebSocket 消息契约保持不变。

音频对齐和切片确认/精修分别直接依赖 MSE/Web Audio 与公共时间轴坐标；它们保留在 `Workbench`，避免把高耦合时间轴逻辑拆到只会转移复杂度的新 hook。

## 视觉与状态规则

- 青色：主进度与播放头；绿色：入点；红色：出点；蓝色：已确认切片和选择；橙色：待确认 AI 候选。
- 右侧队列始终采用单一列表而非状态 Tab：待确认优先，其次导出中，最后已完成。
- 无固定扫描范围时，分析状态使用“分析中 / 已跟进至”类文案，不能以 `100%` 暗示已完成。
- 样式只在本轮修改触及的组件中迁移到现有语义 token；不进行全仓内联样式清扫。浅色主题的调色板覆盖债务不在本轮解决。

## 实施顺序与验证

1. 先调整四区布局、设置抽屉菜单选中态和右侧队列内容归属。
2. 再提取 `useRoomBatchActions` 与 `useClipWorkflow`；每次提取后保持页面行为不变。
3. 每一阶段运行 `npx tsc --noEmit` 与 `python -m pytest tests/test_frontend_stability_guards.py -q --basetemp <writable-dir> -p no:cacheprovider`。
4. 手工验证：多房间录制/停止、对齐、房间选择、时间轴 scrub/I/O/精修、待确认切片、单个与批量导出、持续分析入口及设置抽屉选中态。

## 非目标

- 不重写时间轴、播放控制或坐标转换。
- 不修改后端协议、Zustand 数据结构或导出契约。
- 不将设置页纳入大规模组件重构。
- 不删除或覆盖当前工作区的任何未提交改动。
