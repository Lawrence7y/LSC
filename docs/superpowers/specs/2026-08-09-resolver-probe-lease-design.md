# 解析、媒体探测与流租约设计规格

> 状态：提案  
> 日期：2026-08-09  
> 上游规格：[平台契约与凭据设计规格](2026-08-09-platform-contract-credentials-design.md)  
> 主要代码范围：lsc/platforms、lsc/core 的解析与媒体运行时服务

---

## 1. 目的

把平台返回的候选地址转换为可连接、可评分、可过期和可恢复的流租约，消除“拿到 URL 就认为成功”的不稳定根源。

---

## 2. 处理流水线

    ResolveRequest
      -> 选择适配器
      -> 获取凭据上下文
      -> 解析候选集合
      -> 规范化与去重
      -> 并发受限探测
      -> 硬性校验
      -> 候选评分
      -> 签发 StreamLease

每个阶段都必须接受统一 deadline 和 cancellation。调用方取消后，不得继续刷新凭据或发起新连接。

---

## 3. 规范化与去重

规范化必须：

- 统一协议、容器、画质和线路字段。
- 合并适配器级请求头与候选级请求头，候选级优先。
- 校验 URL scheme，只允许配置白名单中的媒体协议。
- 删除空候选、明显过期候选和完全重复候选。
- 生成不含敏感签名值的 fingerprint。
- 保留不同 CDN、线路、协议、画质和必要请求头的候选。

任何 URL 都不得通过 shell 字符串拼接传递给 FFmpeg；必须使用参数数组。

---

## 4. 探测契约

ProbeRequest 包含候选、完整连接上下文、deadline 和探测预算。探测必须尽量复用实际进样使用的：

- User-Agent、Referer、Origin、Cookie 等请求头。
- 代理和 DNS 策略。
- TLS 和重定向策略。
- FFmpeg 协议白名单与超时参数。

ProbeResult 至少包含：

- success 和 failure_code。
- HTTP 状态或协议错误。
- first_byte_ms 与 probe_duration_ms。
- 可读字节数。
- 容器、视频轨、音频轨和编码信息。
- 媒体时间戳是否前进。
- 估算码率。
- redirect_count。
- server 或 CDN 脱敏标识。

硬性成功条件：

1. 在预算内读到媒体数据。
2. 容器可被解析。
3. 至少存在可消费视频轨；纯音频平台例外必须由能力声明允许。
4. 时间戳在观察窗口内前进。
5. FFmpeg 或探测器可以使用相同上下文再次打开。

只完成 HTTP 200、HEAD 或少量文本响应不算媒体探测成功。

---

## 5. 探测并发和预算

- 单次解析默认最多并发探测 3 个候选。
- 同一平台和账号受 capabilities 的解析与连接并发限制。
- 优先探测历史健康 CDN、用户画质和稳定协议。
- 一旦获得满足阈值的高分候选，可以取消低价值尾部探测。
- 取消必须关闭 socket、子进程和临时文件。
- 单候选超时、总探测超时和整次解析 deadline 分开配置。

---

## 6. 候选评分

评分包含：

- 画质匹配度。
- 首字节延迟。
- 媒体时间戳连续性。
- 音视频轨完整性。
- 历史 CDN 成功率。
- 预计有效期。
- 解析来源可信度。
- 协议与当前运行环境的兼容性。

惩罚项包含：

- 最近 403、429、5xx 或协议错误。
- 首字节过慢。
- 缺少音轨但业务需要音轨。
- 时间戳跳变。
- URL 即将过期。
- 已在当前会话失败。

历史评分按平台、线路和脱敏 CDN 聚合，不得把带签名 URL 作为长期键。

---

## 7. 流租约

StreamLease 至少包含：

| 字段 | 说明 |
|---|---|
| lease_id | 不可复用的租约标识 |
| room_session_id | 所属房间会话 |
| candidate_snapshot | 已脱敏和受控封装的候选 |
| issued_at | 签发时间 |
| expires_at | 硬过期时间 |
| refresh_at | 建议主动刷新时间 |
| probe_summary | 探测摘要 |
| generation | 同一会话的租约代次 |
| invalidation_reason | 失效原因 |

租约规则：

1. expires_at 已到的租约禁止新建连接。
2. 到达 refresh_at 可以后台解析新候选，但当前健康连接不立即中断。
3. 403、410、签名错误、平台明确失效码会使租约立即失效。
4. 网络超时不会直接判定 URL 过期，应先按网络策略重试。
5. 新租约只有在探测成功后才能替换旧租约。
6. 替换采用先建新连接、验证首帧、再切换的方式；资源不足时允许显式降级。

---

## 8. 失败分类与恢复

| 失败类型 | 首选动作 | 是否重新解析 |
|---|---|---|
| DNS、连接重置、瞬时超时 | 同候选短退避重连 | 达到预算后 |
| 403、410、签名失效 | 立即作废租约 | 是 |
| 429 | 尊重 Retry-After 并平台级退避 | 视租约年龄 |
| 5xx | 换候选或换 CDN | 达到短预算后 |
| 容器无法解析 | 标记候选不兼容 | 是或尝试下一候选 |
| 无音轨 | 按业务要求降级或换候选 | 可能 |
| 时间戳不前进 | 断开并换候选 | 是 |
| 凭据失效 | 进入 AUTH_REQUIRED | 凭据恢复后 |
| 主播下播 | 进入 OFFLINE | 按房间轮询策略 |

重试预算至少分为连接级、租约级、房间级。任何一级耗尽后都必须进入 BACKING_OFF 或 FAILED，不能零延迟循环。

---

## 9. 缓存与熔断

- 成功解析缓存的有效期不得超过 recommended_refresh_at。
- 失败缓存按错误类型设置 TTL，AUTH_REQUIRED 不自动高速重试。
- 熔断键使用平台、账号引用和脱敏出口维度，不使用完整 URL。
- 熔断状态属于运行时服务，不得放在平台适配器模块变量。
- 半开探测只允许少量请求；成功后逐步恢复并发。
- 手工“立即重试”仍受最小安全间隔和全局并发限制。

---

## 10. 建议模块

- lsc/platforms/models.py：能力、候选、结果和错误模型。
- lsc/core/stream_resolver.py：解析编排与缓存。
- lsc/core/stream_probe.py：真实媒体探测。
- lsc/core/stream_lease.py：租约签发、刷新和失效。
- lsc/core/recovery_policy.py：错误分类、预算、退避和熔断。

具体文件名允许在评审后调整，但职责不能重新混入 orchestrator.py。

---

## 11. 测试要求

1. 使用本地假 CDN 模拟 200、302、403、410、429、5xx、慢首包和中途断流。
2. 模拟签名 URL 在探测后、连接前以及连接过程中到期。
3. 验证探测与实际连接请求上下文等价。
4. 验证错误候选不会污染成功候选评分。
5. 验证取消后无 FFmpeg、socket 或协程泄漏。
6. 验证租约预刷新不中断健康录制。
7. 验证熔断和半开行为不会形成请求风暴。
8. 验证同一候选在不同账号或代理上下文中不会错误复用。

---

## 12. 验收标准

- 未经探测的候选不能进入主进样连接。
- 解析成功率、探测成功率和建连成功率可分别统计。
- 任意失败都能落入稳定错误分类并得到有限恢复动作。
- 签名 URL 过期不会导致无限复用旧缓存。
- CDN 切换、租约刷新和凭据失效均可在自动化测试中稳定复现。
