# Valorant 回合召回与弱结果终点模型优化设计

## 目标

针对 2026-07-22「保安头子尼克」录制中出现的漏回合和 `model_result` 弱终点，建立可复核的新标注样本，提升回合召回率与回合结束边界准确度。

本轮不改变导出门禁语义，不直接放宽 `pending` 回合的自动导出资格，也不在盲测门禁未通过前替换生产 ONNX 模型。

## 已确认基线

- 原始录制分析快照包含 8 个回合候选；全部为 `pending`。
- R08 的结束证据为 `model_result`，结束置信度为 0.6941，未达到当前 0.8 的强置信度阈值。
- 当前训练模型为五分类相位模型：`non_game`、`buy`、`combat`、`result`、`replay`。
- 现有评估脚本已支持分类指标、回合召回、起止误差 P95、重复回合和强制关闭检查。
- 现有盲测集必须保持不变，用于新旧模型的同条件比较。

## 方案边界

### 数据与标注

以原始完整录制为唯一时间轴，建立独立的新录制样本目录，不把导出 MP4 当作新的完整录像源。围绕 8 个候选回合的起点、终点各提取约 12 秒的密集帧，同时覆盖候选之间的间隔，以发现漏掉的回合。

标注相位帧：

- `buy`：买枪/屏障/准备阶段；
- `combat`：回合进行中；
- `result`：胜负结果或比分变化画面；
- `non_game`、`replay`：非对局和回放画面。

标注时额外记录回合真值 `start_sec`、`end_sec`、`end_reason`，其中 `end_reason` 取 `result`、`next_buy`、`score` 或 `unknown`。低置信度结果帧、长 combat、候选间隔和相位突变帧必须进入 hard-sample 清单。

新录制按连续时间块拆分为 train/validation；禁止把同一边界相邻帧随机分到不同集合。现有 blind/test 数据不改、不回流训练。

### 训练

第一轮只扩充和纠正数据，不改模型结构。复用现有 MobileNetV3-Small、五分类标签、类别加权和 ONNX 导出流程；提高新录制边界 hard samples 的采样权重，并保留每类最低样本检查。

训练产物写入独立版本目录，至少包含：

- ONNX 模型；
- 模型元数据和数据集版本；
- 训练/验证逐类 precision、recall、F1；
- 新录制边界审计报告。

### 评估与发布门禁

先用当前模型在新录制标注集上生成基线，再用新模型在完全相同样本上生成对照。两者都必须在相同 blind/test 集上复测。

本轮重点指标：

- 回合召回率；
- 结束点误差 P95 和最大误差；
- `result` 类 precision/recall；
- 漏回合清单；
- 强置信度回合的边界误差。

保留现有门禁：回合召回率至少 0.90，起止误差 P95 不超过 0.8 秒，且分类和 listed precision 等既有门禁不能退化。任一门禁失败时，只保留为候选模型，不替换 `lsc/analyzer/models/` 下的运行模型。

### 运行时边界

模型只提供逐帧相位预测。`model_result` 弱置信度不能单独闭合可信回合；结束点需要稳定结果帧、比分变化或下一次买枪信号之一进行确认。未满足条件的回合继续保留为 `pending`，并记录未确认原因；不通过放宽门禁来掩盖模型问题。

## 数据流

```text
原始完整录制
  -> 边界候选与间隔抽帧
  -> 人工相位/回合真值标注
  -> 数据一致性审计与连续时间块拆分
  -> 当前模型基线
  -> 新模型训练与独立版本导出
  -> 新录制评估 + 原 blind/test 对照
  -> 门禁通过后再进入运行时替换
```

## 错误处理与可追溯性

- 缺失帧、无法解码、时间戳重复或越界时，标注构建失败并列出具体文件和时间，不静默跳过。
- 每个回合保留稳定 `round_key`，审计报告记录预测起止、真值起止、误差、确认状态和失败原因。
- 训练、评估和导出使用独立输出目录，不覆盖现有模型或原始标注。
- 任何模型替换前必须保存 SHA-256、数据集版本、盲测报告和门禁结果。

## 验证

实现阶段先添加一个最小的标注/评估回归测试，覆盖：

1. 弱 `model_result` 不得被判为可信闭合边界；
2. 候选间隔中的人工回合能被计入回合召回；
3. 新旧模型评估使用同一 blind/test 样本集合；
4. 门禁失败时不会覆盖运行模型。

完成后运行现有 Valorant FSM、连续分析和模型评估测试，并保存命令输出。

## 非目标

- 本轮不重写回合 FSM，不引入新的模型依赖；
- 不把 R08 单个视频硬编码进检测逻辑；
- 不改变 `pending`、`vision_confirmed` 和 `export_deferred` 的产品语义；
- 不将未通过门禁的模型部署到生产路径。
