# 无畏契约混合视觉持续分析设计

日期：2026-07-20

状态：设计已批准（2026-07-20）；下一步为实施计划

## 替代关系

本文取代 `2026-07-19-valorant-hud-round-boundary-design.md` 中以固定 ROI、亮度、连通域和横幅结构阈值作为主边界信号的方案。

本文不取代现有持续任务、多房间时间映射、`round_key`、`clip_queued`、用户精修和时间线契约。新方案必须复用这些链路，不创建第二套切片或导出系统。

## 目标

同时支持以下两类无畏契约直播画面：

- 赛事转播与解说画面，包括舞台、广告、比分板、赛事 Replay、选手摄像头和不同赛事 HUD；
- 主播第一视角，包括游戏原生 HUD、商店、死亡回放、比分板、暂停和直播贴图。

持续分析应从完整回合开始处切入，在回合结束后保留短暂结算反馈，并排除买枪阶段、Replay、广告、舞台和下一回合买枪内容。相较现有实现，优先降低误切、跨回合、超长切片和大段漏检，同时保持可持续实时运行和真实可取消。

## 非目标

- 不为所有 FPS 游戏训练通用视觉模型；本模型只服务无畏契约；
- 不建设模型注册平台、在线训练平台或云端推理服务；
- 不上传用户录像、诊断帧或训练数据；
- 不新增自动导出流程；持续分析仍只负责把候选加入切片列表；
- 不重写多房间同步、时间线或用户精修系统；
- 不继续维护音频、文字 OCR、固定 HUD 阈值三套并行边界检测器；
- 不以文件时长、最大回合时长或 HUD 消失强行闭合回合。

## 现场证据与根因

### 当前实现结果

固定 HUD 结构方案已经在脱离分支的 `.worktrees/valorant-hud-boundary` 工作树中实现并进行过多轮实测。该工作树包含用户和既有实验改动，必须保留，不得整体覆盖或直接作为干净实现基线。

现有诊断结果显示：

- 一个样本仅识别到 3 个买枪帧；
- 两段完整录像分别出现 137–240 秒的漏检空洞；
- 多个候选被闭合为 150–180 秒；
- 实际边界帧中出现舞台镜头作为起点、Replay 作为终点；
- 为修复不同画面，分类器逐步增加买枪横幅、商店网格、结算大字、HUD 缺失和时长阈值，代码与阈值继续膨胀，但跨布局泛化仍不稳定。

### 根因

1. 当前分类器把固定区域的亮度、方差、横向条带和连通域当作 HUD 语义。这些特征同样会出现在舞台灯光、赛事包装、Replay、比分板和直播贴图中。
2. 固定 ROI 假设赛事转播和第一视角共享相同布局；分辨率、裁切、旋转、转播模板或摄像头叠层变化后假设失效。
3. 状态机把多数“有效但非买枪”画面当作交战。一次假买枪后，舞台、Replay 或普通赛事画面即可打开回合。
4. 1 FPS 只决定时间分辨率，不能修复错误的帧语义。提高采样频率会更频繁地产生同类误判。
5. 现有 FFmpeg 抽帧是阻塞调用。超时或停止时，async 任务可结束并释放信号量，但底层线程和 FFmpeg 仍可能运行。
6. 当前根分支未包含脱离工作树中的 HUD 结构实现。实施前必须从当前分支建立清晰基线，只选择性复用经过验证的通用链路。

因此，修复点是“帧语义识别、独立数字锚点、时间证据融合和可取消扫描生命周期”，不是继续增加固定阈值。

## 方案比较

### 双规则配置

分别为第一视角和赛事转播维护 ROI、模板和阈值。实现成本较低，但每个赛事 HUD、直播裁切和分辨率变化都需要重新调参，不能解决长期泛化问题。

### 纯视觉模型

让模型直接输出每帧状态。它比手写结构规则更能适应画面变化，但单帧概率抖动不足以保证时间一致性，比分和计时器等强事实也没有被利用。

### 混合视觉方案

采用轻量视觉分类模型识别场景语义，使用比分和计时器作为独立锚点，再由确定性状态机融合时间证据。1 FPS 粗扫寻找候选，候选附近 8–10 FPS 密扫精修边界。

本设计采用混合视觉方案。它在跨布局能力、可解释性、边界精度和运行成本之间最平衡。

## 总体架构

```text
增长中的录像文件
  -> 前向游标按 1 FPS 抽取新帧
  -> 轻量 ONNX 五分类模型
  -> 候选点顶部小区域数字锚点
  -> 确定性时间状态机
  -> 候选点前后 5 秒密扫精修
  -> 证据分级与闭合门禁
  -> 现有 round_key / 多房映射 / clip_queued
```

### 模块职责

#### 模型包装器

新增一个无畏契约专用模型包装器，负责：

- 校验模型和元数据；
- 懒加载 ONNX session；
- 复用现有 CUDA、DirectML、CPU provider 选择顺序；
- 批量预处理和推理；
- 返回五类概率，不包含状态机和业务门禁。

不新增通用模型注册表。

#### 分析器

`lsc/analyzer/round_detector.py` 负责：

- 使用 FFmpeg 按时间范围抽帧；
- 调用模型包装器；
- 仅在候选附近读取顶部比分和计时器；
- 生成统一帧证据；
- 对候选边界执行局部密扫。

音频、旧文字状态 OCR 和固定 HUD 阈值不得参与 `valorant_round` 的边界生成。

#### 时间状态机

现有 HUD 边界状态机缩减为纯时间证据融合器，负责：

- 稳定帧序列；
- `buy -> combat -> result` 状态转换；
- 数字锚点一致性检查；
- 候选打开、闭合、丢弃和重新同步；
- 生成稳定的粗粒度回合身份。

状态机不读取图片、不调用 OCR、不执行 FFmpeg。

#### 持续任务

`python-backend/handlers/room_handler.py` 继续负责：

- 持续任务生命周期；
- 前向游标和扫描批次；
- 全局分析信号量；
- 多房间时间映射；
- `round_key` 去重和 upsert；
- `clip_queued` 与状态广播。

检测细节不得继续堆入 handler。

## 模型设计

### 类别

模型输出以下五类概率：

| 类别 | 含义 |
|---|---|
| `non_game` | 舞台、广告、选人、桌面、加载、赛后或其他非回合画面 |
| `buy` | 买枪、准备或屏障阶段 |
| `combat` | 正常回合交战画面 |
| `result` | 回合胜负结算画面 |
| `replay` | 赛事 Replay 或死亡回放 |

赛事转播和第一视角使用同一个模型与同一类别语义，不增加两套运行时分类器。

### 模型格式

- 架构采用 `MobileNetV3-Small` 级别的轻量卷积分类器；
- 输入为完整画面等比例缩放并补边到 `224x224`；
- 导出为 INT8 ONNX；
- 目标模型体积为 3–5 MB；
- 训练使用已有 PyTorch AI 环境；
- 程序运行只依赖已有 ONNX Runtime；
- CPU provider 是最终兼容路径，CUDA 与 DirectML 是可选加速路径。

### 模型元数据

模型旁保存固定格式的元数据，至少包含：

- 模型版本；
- 类别顺序；
- 输入尺寸；
- 颜色通道顺序；
- 归一化参数；
- 分类阈值版本；
- 模型 SHA-256；
- 数据集版本。

任一契约不匹配时拒绝加载，不猜测默认值。

## 训练数据设计

### 数据规模与覆盖

- 初始目标 2500–5000 张人工确认帧；
- 每类不少于约 400 张；
- 赛事转播和第一视角分别至少覆盖 3 个独立录像会话；
- 覆盖不同主播、赛事模板、分辨率、直播裁切和叠层；
- 至少为每种输入类型保留一段完整录像作为最终盲测。

### 困难负样本

必须专门覆盖：

- 舞台与选手席镜头；
- 广告和赛事包装；
- 选人和地图加载；
- 游戏商店和比分板；
- 暂停和技术暂停；
- 死亡回放与赛事 Replay；
- 主播摄像头和直播贴图；
- 高对比中央字幕；
- HUD 被局部遮挡或缩放的画面。

这些样本是当前误切的主要来源，不能只用清晰游戏 HUD 训练。

### 边界样本

买枪结束、结算出现和 Replay 切入前后 3 秒应提高抽帧密度。普通稳定区可稀疏采样，避免大量相邻重复帧压倒边界样本。

### 划分与增强

- 训练、验证和测试按完整录像分组；
- 同一录像的相邻帧不得跨集合；
- 允许亮度、JPEG 压缩、轻微缩放和模糊增强；
- 不使用破坏 HUD 空间关系的大幅随机裁剪；
- 分类概率阈值只能依据验证集确定；
- 最终测试录像在训练和调参期间不可查看其标签结果。

### 数据保存

- 原始录像和完整训练集不提交 Git；
- 仓库保存训练清单格式、少量回归夹具、训练脚本、评估脚本、最终 ONNX 和元数据；
- 低置信诊断帧只可通过显式本地命令导出；
- 程序不得自动上传画面。

## 帧证据

每个粗扫或密扫帧生成统一证据：

```text
timestamp
class_probabilities
predicted_class
timer_seconds?
left_score?
right_score?
model_version
```

数字字段读取失败是允许状态。读取失败不能被解释为 0，也不能单独否决高置信视觉序列。

RapidOCR 不再每秒运行。它只在模型检测到买枪、结算或状态转换候选时读取顶部小区域。数字结果用于确认和提高置信，不负责识别语言相关状态文字。

## 回合状态机

### 状态

```text
WAIT_BUY
  -> stable buy
WAIT_COMBAT
  -> stable combat
ROUND_OPEN
  -> stable result or verified score increment
WAIT_BUY
```

### 通用约束

- 单帧分类不得触发状态转换；
- 粗扫使用连续证据稳定转换；
- 密扫在 10 FPS 下要求至少连续 3 帧满足目标状态；
- `non_game` 和 `replay` 永远不能打开或闭合回合；
- 从交战中途开始时不猜起点，等待下一次完整 `buy -> combat`；
- 连续非游戏画面超过 5 秒使未闭合候选失效；
- 开放回合超过 150 秒时丢弃并重新同步，不产生强制闭合切片；
- 停止或取消持续分析时丢弃开放回合。

### 数字一致性

- 计时器进入正赛时段可确认买枪结束；
- 比分单侧增加 1 可确认上一回合结束；
- 比分减少、同时跳变超过 1 或无法保持顺序时视为 OCR 冲突；
- OCR 冲突降低证据等级并触发局部重读，不能直接写边界；
- 赛事切换、半场换边或新地图开始必须先经过 `non_game/buy` 重新锚定。

## 边界语义

### 起点

切片起点是买枪阶段结束后的第一张稳定交战帧。

粗扫发现 `buy -> combat` 后，在候选点前后 5 秒以 8–10 FPS 密扫。起点取连续 3 帧稳定为 `combat` 的第一帧。计时器同时进入约 `1:40` 的正赛时段时提高证据等级。

切片不包含当前回合买枪阶段。

### 回合结束事件

回合结束事件由以下任一强序列确认：

- 稳定 `result`，并读取到比分单侧增加 1；
- 高置信、完整的 `buy -> combat -> result` 序列，数字读取暂时失败；
- 比分增加 1 后，向前局部密扫找到稳定结算或交战退出点。

Replay 本身不是结束证据。

### 成片终点

成片终点默认是回合结束事件后 1.5 秒，让观众看到胜负结果。若 1.5 秒内已进入 Replay、非游戏画面或下一回合买枪，则在该状态第一帧前截断。

如果只检测到下一回合买枪但没有上一回合结算或比分证据，分析器向前回溯密扫。仍无法确认时不得自动生成该切片。

所有回合使用半开区间 `[start, end)`。

## 粗扫与局部精修

### 粗扫

- 时间轴采样密度固定为 1 FPS；
- “1 FPS”不表示每秒启动一次 FFmpeg；
- worker 每 5 秒处理一批新增内容；
- 距离正在写入的直播尾部保留 2–3 秒安全延迟；
- 只处理 `last_processed_ts` 之后的新帧；
- 保留 2 秒抽帧重叠，并按时间戳去重；
- 落后时按时间顺序分段追赶，禁止跳到最新尾部；
- 资源压力可延长 worker 触发间隔，但不得降低录像时间轴采样密度。

### 局部精修

- 仅对状态转换候选执行；
- 默认窗口为候选点前后 5 秒；
- 采样密度为 8–10 FPS；
- 普通帧只执行模型推理；
- 数字 OCR 仅在候选子区间按需运行；
- 临时帧在本次精修完成后立即释放；
- 精修后的边界更新原候选，不产生新回合身份。

### 停录收尾

停录后从当前游标继续处理剩余安全尾部，不默认全文件重扫。只有游标状态损坏或模型版本在任务中途改变时，才允许一次显式全文件重建，并记录原因。

## 证据等级

### 视觉确认

起点和终点均完成密扫，并满足完整时间序列及强证据。结果加入切片列表，使用 `confirm_status='vision_confirmed'`。

### 待人工确认

回合完整闭合，但一个边界只有中等证据。结果可加入切片列表，使用现有 `confirm_status='pending'`，不得作为已确认片段。

### 识别失败

开放尾、超时、状态冲突、只有单一弱信号或超过最大开放时长。结果只计入诊断，不调用切片入列链路。

具体模型概率阈值由验证集确定并随模型元数据发布。业务代码只消费经过版本校验的阈值，不散落魔法数。

## 回合对象与稳定 key

回合对象至少包含：

```text
start
end
round_key
phase = combat
confirm_status
boundary_source = valorant_hybrid_v1
start_by = model_buy_exit
end_by = model_result | model_score
start_confidence
end_confidence
boundary_confidence
boundary_evidence
model_version
```

`boundary_evidence` 只保存短证据标签，不保存完整帧或大段 OCR 文本。

回合在粗扫打开时使用主房录制会话 ID 与粗扫起点生成 `round_key`。密扫改变精确边界时不得重算 key。所有目标房间共享该 key，只转换本地时间坐标。

同一回合获得更强证据时通过 `clip_queued(upsert=true)` 更新。用户已经精修或导出的回合被冻结，后续分析不得覆盖。

## 切片列表与导出契约

- 持续分析继续调用现有 `list_only=True` 路径；
- `vision_confirmed` 表示视觉边界达到自动确认门，但不会自动启动 FFmpeg 导出；
- `pending` 仍需用户确认或精修；
- 新增 `vision_confirmed` 到前后端确认状态枚举和“可导”判断；
- 前端显示“视觉确认”或“待确认”；
- 前端可显示简短证据，例如“买枪退出 + 比分变化”；
- 不得用 `ocr_confirmed` 表示混合视觉模型结果；
- 不创建新的导出队列、持久化表或 WebSocket 事件类型。

## 多房间和时间轴

只在主房运行模型和数字锚点分析。闭合回合继续通过 `recording_start_mono` 与 `content_offset` 映射到目标房间。

`preview_local`、`common` 与 `recording_local` 三套坐标不得混用。模型和状态机只产生主房 `recording_local` 秒数；公共轴与其他房间的映射继续由现有 handler 完成。

映射失败时主房可正常入列，失败房间走现有提示与降级路径。不得扩大边界来掩盖房间间偏差。

## 可取消扫描生命周期

### FFmpeg

抽帧必须使用可观察、可终止的子进程执行方式。现有阻塞式 `run_hidden(timeout=...)` 不能作为持续视觉扫描的最终实现。

取消或超时时：

1. 设置任务取消标志；
2. 终止 FFmpeg 进程树；
3. 等待子进程退出；
4. 等待当前短推理批次结束；
5. 清理临时帧；
6. 最后释放 `_analysis_semaphore`。

信号量不得在线程或子进程仍运行时释放。

### Worker 状态

`_continuous_tasks` 状态必须保留到 worker、FFmpeg 和推理批次全部退出。停止请求先进入 `stopping`，实际退出后再广播 `idle`。

停止 handler 不得在仅调用 `task.cancel()` 后立即返回“已停止”。

### 推理取消

ONNX 按小批次运行，在批次之间检查取消。不强制中断一次短 `session.run()`；批次大小必须保证停止延迟满足验收目标。

## 性能策略

- ONNX 普通帧批量推理；
- 复用单例 session，禁止每批重新加载模型；
- RapidOCR 只在候选附近运行；
- 已处理时间戳不得重复推理，密扫重叠除外；
- CPU provider 必须可用；
- CUDA 或 DirectML 初始化失败可回退 CPU；
- 稳态处理速度必须长期高于录像增长速度；
- 状态广播包含 `analysis_lag_sec`、模型版本、provider、扫描阶段和最近错误。

## 错误处理

| 情况 | 行为 |
|---|---|
| 模型缺失或 SHA-256 不匹配 | 禁用本次 Valorant 自动切片并报告错误 |
| 元数据类别或预处理契约不匹配 | 拒绝加载，不使用默认值猜测 |
| GPU/DirectML 初始化失败 | 回退 CPU，并广播实际 provider |
| ONNX 推理持续异常 | 停止本次任务，不回退旧算法 |
| FFmpeg 抽帧超时 | 不推进游标，终止进程后重试同一段 |
| 数字 OCR 失败 | 保留模型证据；按证据等级决定确认或待确认 |
| 数字 OCR 冲突 | 局部重读；仍冲突则降级或丢弃 |
| 长期低置信 | 保留诊断计数，不生成切片 |
| 开放回合超过 150 秒 | 丢弃并重新锚定，不强制闭合 |
| 停止持续分析 | 丢弃开放回合并真实等待资源退出 |
| 停录 | 从游标处理剩余尾部，不默认全文件重扫 |

所有失败路径都禁止回退到音频、旧文字 OCR 或固定 HUD 阈值生成边界。

## 测试策略

### 模型契约测试

- 正确模型和元数据可以加载；
- SHA-256、类别顺序、输入尺寸或归一化不一致时拒绝加载；
- provider 选择遵循 CUDA、DirectML、CPU 的现有平台规则；
- provider 初始化失败可回退 CPU；
- 缺失模型时返回可诊断错误，不产生候选。

### 分类评估

评估脚本按完整录像读取测试清单，输出：

- 五分类混淆矩阵；
- 每类 precision、recall、F1；
- Macro F1；
- 按赛事转播和第一视角分别统计的指标；
- 低置信与高置信误判帧清单。

### 纯状态机测试

使用人工概率与数字序列，不调用 FFmpeg 或模型：

- 完整 `buy -> combat -> result` 只闭合一个回合；
- 单帧抖动不转换；
- 从 combat 中途启动不生成回合；
- Replay 和 non_game 不打开或闭合；
- 比分增加确认终点；
- 比分冲突触发重读或降级；
- 超过 150 秒只丢弃，不输出强制长度切片；
- 取消和停录丢弃开放尾；
- 重叠时间戳不重复喂入；
- 边界精修不改变 `round_key`。

### 局部精修测试

- 10 FPS 序列取连续稳定状态的第一帧；
- 起点不包含买枪尾帧；
- 终点保留 1.5 秒结算；
- Replay 或下一买枪提前出现时截断；
- 没有强终点时不生成视觉确认切片；
- FFmpeg 失败不推进精修或粗扫游标。

### 生命周期测试

必须使用运行时行为测试，不以源码字符串检查代替：

- 阻塞扫描超时后，第二个任务不能提前获得信号量；
- 停止请求会终止伪 FFmpeg 子进程并等待退出；
- `_continuous_tasks` 在资源退出前保持 `stopping`；
- 停止完成后无孤儿子进程或后台扫描线程；
- 模型批次之间响应取消；
- 停录收尾只从游标继续。

### 后端与前端契约测试

- `vision_confirmed` 和 `pending` 均走 `list_only=True`；
- 识别失败不调用 `clip_queued`；
- 首次入列增加条目，后续只 upsert；
- 用户精修后拒绝自动覆盖；
- `vision_confirmed` 在前端属于可导状态并显示正确标签；
- 多房映射共享 `round_key`，各房间只改变本地起止时间；
- 旧音频、OCR 和 HUD 阈值结果不能进入 Valorant 列表路径。

### 完整录像盲测

完整录像盲测是发布门，不以单帧夹具通过替代。评估脚本比较人工标注回合和最终 `clip_queued`，同时输出误检、漏检、起止误差、超长切片、重复 key 和非游戏画面进入情况。

## 验收标准

### 模型

- 测试集五分类 Macro F1 不低于 0.94；
- `buy` 和 `result` precision 不低于 0.97；
- `replay` 和 `non_game` recall 不低于 0.95；
- 赛事转播和第一视角分别满足门槛，不能只看合并平均值。

### 回合质量

- 完整回合 recall 不低于 90%；
- 已入列切片 precision 不低于 97%；
- `vision_confirmed` 中不得出现舞台、广告、Replay、跨两个回合或交战中途起止；
- 起点和目标终点绝对误差 P95 不超过 0.8 秒；
- 任一 `vision_confirmed` 边界误差不得超过 2 秒；
- 不得生成因超时、HUD 消失或最大时长而强制闭合的 150/180 秒切片；
- 同一回合重复扫描不得重复添加；
- 多房映射后的内容时刻误差不超过现有同步误差预算。

### 性能与生命周期

- 支持测试机器上持续分析稳态延迟 P95 不超过 10 秒；
- CPU-only 降级时稳态延迟 P95 不超过 15 秒；
- 处理速度长期不低于录像增长速度；
- 点击停止后 3 秒内进入 `idle`；
- 进入 `idle` 时 FFmpeg、worker 和信号量均已真实释放；
- 模型或 FFmpeg 故障时不得产生猜测切片；
- 停录收尾不得默认全文件重扫。

### 回归

- 所有新增与受影响测试通过；
- 完整测试套件相较实施前记录的基线不得新增失败；
- 当前已知无关失败必须逐项记录，不能概括为“测试陈旧”。

## 发布顺序

1. 建立训练清单、标注工具和完整录像人工真值；
2. 训练并导出 INT8 ONNX 与元数据；
3. 在现有两个失败样本和独立测试录像上离线评估；
4. 完成纯状态机、精修、生命周期和协议测试；
5. 各选择一场赛事转播和第一视角进行 shadow 运行，只生成报告、不入列；
6. 所有验收门通过后切换 `valorant_round` 主路径；
7. 删除 Valorant 音频、旧文字 OCR 和固定 HUD 阈值边界主路径；
8. 保留通用音频能力供其他分析模式使用；
9. 运行完整回归与性能验收后再发布。

生产版本不长期保留新旧检测器开关。shadow 仅用于发布前验证，切换完成后删除兼容分支。
