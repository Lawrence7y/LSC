# 使用习惯十四项修复 — 设计说明

> 日期：2026-07-16  
> 来源：工作台逻辑/习惯审查（标记→对齐→切片→确认→导出/分析）  
> 对应计划：`docs/superpowers/plans/2026-07-16-ux-habit-fourteen-fixes.md`

## 目标

消除与直播切片用户习惯冲突的命名、门禁绕过、无预览误标、单房分析不可用等问题；不改变墙钟映射与「预览/录制独立」核心契约。

## 原则

1. **名实一致**：按钮/toast 说的事必须与行为一致（尤其「导出」一词）。
2. **质量优先不可被批量路径绕过**：pending/refining 不得在无显式确认下自动变 `user_confirmed` 再导出。
3. **无预览不标点**：I/O 依赖预览播放头；无 MSE 时禁止标记。
4. **改动面最小**：优先改文案、门禁、快捷键行为；避免大重构。
5. **文档与代码同步**：CLAUDE.md 快捷键与对齐采声时长与实现一致。

## 十四项决策摘要

| # | 问题 | 修复决策 |
|---|------|----------|
| 1 | 「分析导出」名实不符 | 工具栏改为「分析」；弹窗按钮保持「开始分析并入列」/「开始持续分析」 |
| 2 | 导出全部/Ctrl+E 静默确认 pending | 批量路径不再 auto-confirm；pending 须走单条「确认」或「确认并导出」；Ctrl+E 同规则 |
| 3 | 单房不能一次性分析 | 非持续模式允许 `target_room_ids.length === 1` |
| 4 | 无预览 I/O 落到 0 | 无启用预览或无 video 时 warning 并 return |
| 5 | 未对齐多房 I/O | ≥2 房且未 `align ready` 时 toast 警告仍允许标记（不硬拦，避免打断急切切片） |
| 6 | 拖标记近似不够显眼 | ClipList 增加「近似」Tag；导出近似条二次 Modal 确认 |
| 7 | 停录文案暗示会导出 | 改为「收尾确认回合入列」，去掉「导出」 |
| 8 | M 多选翻转混乱 | M 仅作用于「主选」一间（单选或 reference/first）；全选静音仍用工具栏按钮 |
| 9 | 对齐失效清空公共入出点 | 清空 common 标记时保留各房 room.mark_*；toast 说明「房间本地入出点仍在，公共轴需重标」 |
| 10 | 分析弹窗展示无用导出预设 | 非持续同步分析去掉导出预设 Select（预设改在确认导出时选） |
| 11 | 快捷键文档过时 | 更新 CLAUDE.md：Ctrl+1 工作台、Ctrl+2 设置 |
| 12 | R 混合状态同时开停 | 若同时有 toStart 与 toStop：只处理停（二次确认），并 info「未录制房间未启动，请再次按 R」 |
| 13 | 对齐 8s 无分步说明 | loading 文案改为「采集预览音频（约 8 秒）…」；CLAUDE.md 改为 8s |
| 14 | 分析目标冻结难改 | Modal 打开期间若 `selectedRoomIds` 变化则同步刷新 `continuousTargetRoomIds`（并校正 main） |

## 非目标

- 不改墙钟导出公式、不改共享进样默认、不自动导出 AI 切片。
- 不引入 Dashboard 页面。
- 不强制未对齐多房禁止 I/O（仅警告）。

## 验收

每项在计划 Task 中有可运行检查（pytest / 前端断言字符串 / 手工步骤）。全部完成后跑相关 pytest 与 `npx tsc --noEmit`（lsc-electron）。
