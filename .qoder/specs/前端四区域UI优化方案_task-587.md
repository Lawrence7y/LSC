# 前端四区域 UI 优化方案

## 设计原则（全程不可违反）

- **13 项冻结交互不变**：scrub 松手才 seek、Shift/Ctrl 打标、磁吸优先级、Live 状态机、DVR 紫标等，优化后逐项回归验证
- **设计一致性**：仅使用 tokens.css 语义变量（--brand-*/--bg-*/--text-*/--state-*）、memo+自定义比较器、ref 稳定回调、乐观 UI；dark/light 双主题都要核对
- **按钮精简**：移除低频冗余、合并流程化动作；**风格适配**：深色分层、teal 对比

---

## 一、持续分析状态栏（AnalysisProgress）

**现状问题**：全部信息平铺一行，用户无法秒答「在干什么 / 进度如何 / 我要做什么」；phase、analysis_stage、scan_reason、round_phase 四套状态概念混杂；「N秒前更新」与全零导出队列常态占位。

**优化：三段式状态条**

1. **主状态区**：大号状态动词（扫描中/收尾中/等待录制/已完成）+ 脉冲点，副标题一句人话（如「增量扫描 1480–1520s · 音频推进」），由单一纯函数 `derivePrimaryStatus(status, summary)` 推导 {verb, detail, tone, nextAction}，memo 化
2. **进度区**：进度条加宽（flex，上限 240px），下方小字「已分析 24m40s / 已录 25m10s · 滞后 30s」（用后端已有的 analysis_lag_sec，比百分比直观）
3. **行动区**：
   - chips 精简：「入列 N」「待调 N」（N>0 时 warning 色且可点击滚动到切片列表）；导出队列仅在有活动时显示为单个「导出 n/m」chip；「N秒前更新」删除（心跳由脉冲点表达）
   - 下一步引导：待确认>0 显示「去确认」链接；等待收尾显示「请先停录」；finalizing 显示预计时长；phase=stopping 显示「停止中…」（与现有状态机对齐）
   - 相位 chip（valorant）保留但降为次要小字

涉及文件：AnalysisProgress.tsx（compact 与卡片两种模式同步精简）。

---

## 二、切片列表（ClipList）

**现状问题**：主操作（导出）是 link 文本样式权重过低；6 个纯图标按钮学习成本高；多房切片无房间归属标识；待确认需逐条处理；空态无引导。

**优化点**

1. **头部工具条**：「导出全部/导出所选」升级为带图标小按钮（主操作 brand 色）；计数改为 chips「共 N · 待调 N(warning) · 可导 N(success)」；待调>0 时提供「全部确认」（批量走现有 handleConfirmClip boundsOnly 路径）
2. **行内**：多房时标题行前加房间 chip（单房隐藏）；pending 与「近似」两个 Tag 合并（近似并入 tooltip）；证据文本改为 ⓘ 图标 hover 展示；导出中进度条原地替换操作按钮区（不再独占一行）；操作按钮保留图标但统一 tooltip 文案（行为不变）
3. **空态**：Empty +「启动持续分析」按钮（直接打开分析 Modal）+ 引导文案
4. 冻结：点击行选中跳转、checkbox 多选、确认/导出/删除语义全部保留

涉及文件：ClipList.tsx 为主，Workbench 传参微调。

---

## 三、底部时间线（Timeline，仅视觉层，不碰交互）

**现状问题**：刻度标签 9px 偏小；AI 回合带只有色块无标签、点击目标小；播放头层级弱；「回直播」入口隐蔽。

**优化点**

1. **刻度**：次刻度标签 9→10px；关键阶段标签加半透明 pill 底（--bg-tertiary 80%）避免与波形重叠
2. **AI 回合带**：带内显示回合标签（R01/R02，宽度足够时）与时长；pending 用虚线边框/斜纹、confirmed 实色（与切片列表状态语义一致）；hover 提亮 + tooltip（时段/时长/状态）；点击行为不变
3. **播放头**：2→3px 加品牌色 glow，scrub 中变色（不改变 scrub 逻辑）
4. **回直播**：偏离直播沿时，时间线右端出现浮动「回直播」按钮（DVR 紫标与 followLive 状态机不动）
5. **时间码行**：左起点 / 中央大字当前播放时间 / 右终点三段；轨道区 min-height 68→76px

涉及文件：Timeline.css + Timeline/index.tsx 渲染层（交互 handler 一律不动）。

## 四、设置页面（Settings）

**现状问题**：单列超长无导航；「录制设置」一组 17 项混杂录制/导出/AI/路径；保存模型不一致（部分立即保存、部分统一保存，用户无法预期生效时机）；原生 select 与 antd 风格不统一。

**优化点**

1. **左侧 sticky 锚点导航**（宽屏显示窄屏隐藏）：通用 / 预览体验 / 录制与编码 / AI 分析 / 存储与草稿 / 平台账号 / 快捷键 / 关于与日志
2. **重新分组**：
   - 预览体验：预览画质（从录制设置拆出，它影响预览不影响录制文件）
   - 录制与编码：画质/分辨率/帧率/音频/编码器/参数/预设/码率/CRF
   - AI 分析：OCR 加速/共享进样/并发导出数/默认导出预设
   - 存储与草稿：存储路径/剪映草稿目录
3. **保存模型统一为「立即保存」**：所有变更即时落盘 + 轻 toast（与现有 OCR/并发项一致），移除底部统一保存按钮；失败时该行标红并就地显示错误
4. **控件统一**：原生 select 全部替换为 antd Select（small）；ToggleSwitch 沿用
5. **系统环境**：状态点+版本+路径单行化，重新检测 icon 化置区块右上角；日志移至「关于」之后并加「打开日志目录」

涉及文件：Settings/index.tsx 单文件重构，抽 SettingsSection/SettingsRow 子组件；样式收敛到现有 tokens。

## 五、实施分期

| 期 | 范围 | 理由 |
|---|---|---|
| **P0** | 状态栏 + 切片列表 | 最高频使用，配合刚修完的切片链路直接提升体验 |
| **P1** | 时间线视觉层 | 纯 CSS/渲染层，风险最低 |
| **P2** | 设置页重构 | 单文件、无运行态依赖，最后做 |

## 六、验收

- 13 项冻结交互逐项回归（scrub/打标/磁吸/Live/DVR/精修快捷键）
- 同步更新 guard 测试中的源码断言（test_frontend_stability_guards / test_cross_feature_guards）
- dark/light 双主题截图核对；1280px 窄窗无遮挡无横向滚动
- tsc 零错误 + 相关 pytest 全绿

## 七、明确不做

- 不改任何交互行为、快捷键、状态机
- 不引入新色值/新字体/新组件库
- 不动 RoomCard、ControlBar 功能结构（时间线仅视觉层）
- 不重构 tokens.css 的 M21 技术债（light 覆盖问题另案处理）
